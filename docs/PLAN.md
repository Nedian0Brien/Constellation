# Constellation 기획서

## 1. 한 줄 정의

특정 연구 분야의 논문 초록을 대량 수집해 **의미 공간에 배치하고**, 그 공간이 **시간에 따라 어떻게 갈라져 왔는지**를 탐색 가능한 지도로 만든다.

## 2. 전제 조건 (확정된 것)

| 항목 | 결정 |
|---|---|
| 데이터 소스 | Scopus 권한 미확보 → **OpenAlex를 1차 소스로 시작**, Scopus는 어댑터로 나중에 연결 |
| 즉시 준비물 | OpenAlex API 키 — 발급 완료, `.env`에 보관 (gitignore 대상) |
| 첫 대상 분야 | **RAG / IR** — 개발 내내 들여다볼 검증용 코퍼스 |
| 실사용 분야 | **피지컬 AI**, **온디바이스 AI** — M1 이후 적용 |
| 결과물 | 로컬 웹앱 (Python 백엔드 + 브라우저 프론트) |
| 규모 | 1천 ~ 1만 편 |
| 임베딩 | 로컬 오픈모델 (RTX 5080 16GB 활용) |

## 3. 이 프로젝트가 답하려는 질문

산점도 하나를 그리는 게 목적이 아니다. 아래 네 질문이 각각 다른 시각화를 요구한다.

1. **구조** — 이 분야는 어떤 주제 덩어리로 이루어져 있는가?
2. **갈래** — 그 덩어리들은 언제 갈라졌고, 무엇에서 뻗어 나왔는가?
3. **계보** — 특정 논문의 조상과 후손은 누구인가?
4. **대상** — 각 갈래는 *무엇을* 연구 대상으로 삼고, *어떤 방법*을 쓰는가?

## 4. "갈래"를 계산하는 세 가지 방법

이 프로젝트의 핵심이자 가장 어려운 부분. 세 방법은 서로 다른 질문에 답하므로 **셋 다 만들고 교차 검증**한다.

### A. 시간 슬라이스 흐름 (주력)

> "2015년의 주제 X가 2020년에는 X1, X2로 갈라졌다"

**계산 방법**
1. 코퍼스를 시간 윈도우로 자른다 (예: 3년 폭, 1년 간격 슬라이딩)
2. 각 슬라이스에서 **독립적으로** 클러스터링한다
3. 인접 슬라이스의 클러스터 쌍 `(C_t, C_{t+1})` 사이 연결 강도를 계산한다:
   - **인용 흐름** — `C_{t+1}`의 논문들이 `C_t`의 논문을 인용한 비율 ← *가장 인과적으로 타당*
   - **의미 유사도** — 두 클러스터 중심 임베딩의 코사인 유사도
   - **저자 연속성** — 두 클러스터에 공통으로 등장하는 저자 비율
4. 이 세 신호를 가중 결합해 alluvial(Sankey) 다이어그램의 흐름 폭으로 쓴다

**읽는 법** — 흐름이 하나에서 둘로 벌어지면 갈래가 뻗은 것, 둘이 하나로 합쳐지면 수렴한 것, 흐름이 끊기면 그 주제가 소멸한 것.

**한계** — 슬라이스별 독립 클러스터링은 불안정하다. 클러스터 개수가 해마다 튀면 흐름도가 지저분해진다. 대응: 슬라이스마다 `min_cluster_size`를 슬라이스 크기에 비례시키고, 흐름 가중치에 하한(threshold)을 둬서 잔가지를 쳐낸다.

### B. 계층 구조 (보조 — 내비게이션용)

> "분야 → 하위 분야 → 세부 주제"

전체 임베딩에 대한 계층적 클러스터링. HDBSCAN의 condensed tree를 그대로 쓸 수 있어 추가 연산이 거의 없다. 시간과 무관한 **구조적** 갈래이며, 사이드바 트리 내비게이션과 지도 줌 레벨별 라벨링에 쓴다.

### C. 인용 메인패스 (심화)

> "이 논문 계열의 핵심 계보는 A → B → C → D"

인용 DAG에 SPC(Search Path Count) 가중치를 매기고 가장 무거운 경로를 뽑는다. 논문 **개별** 단위의 실제 계보라 가장 구체적이지만 시야가 좁다. 특정 클러스터를 선택했을 때 심화 뷰로 제공.

### 교차 검증이 필요한 이유

UMAP의 클러스터 간 **거리는 신뢰할 수 없다** (지역 구조만 보존). "A와 B가 지도에서 가까우니 관련 있다"는 주장은 근거가 약하다. 인용 흐름(A)과 메인패스(C)는 실제 인용 관계에 기반하므로, 지도상의 인접성이 실제 지식 전파와 일치하는지 확인하는 대조군 역할을 한다. **이 한계는 UI에 명시한다.**

## 5. 시각화 뷰

네 개 뷰가 하나의 선택 상태(selection)를 공유한다. Map에서 클러스터를 고르면 Flow에서 해당 흐름이, Lineage에서 해당 계보가 하이라이트된다.

### Map (2D) — 진입점
UMAP 2D 산점도. 논문 1점 = 1개 마커.
- 밀도 컨투어를 깔아 "덩어리"를 눈에 보이게
- 줌 레벨에 따라 라벨 계층 전환 (멀리서는 대분류, 가까이서는 세부 주제)
- 색상 인코딩 전환: 클러스터 / 발행연도 / 피인용수 / 선택한 패싯
- 시간 슬라이더 — 범위를 좁히면 해당 기간 논문만 남고 나머지는 흐려짐

### Flow — 갈래 흐름도 (핵심 차별화)
4.A의 alluvial 다이어그램. 가로축 = 시간, 세로 띠 = 클러스터, 띠 사이 흐름 = 연결 강도.
흐름에 마우스를 올리면 그 흐름을 만든 실제 인용 관계(어떤 논문이 어떤 논문을 인용했는지) 목록이 뜬다.

### Lineage — 인용 계보
선택한 논문/클러스터를 중심으로 한 인용 DAG. Y축을 발행연도로 고정해 시간 흐름이 위에서 아래로 읽히게 배치. 메인패스는 굵게, 나머지는 얇게.

### Sky (3D) — 조망
UMAP 3D. 프로젝트 이름의 근거. 인용 엣지를 별자리 선처럼 그린다.
**주의** — 3D는 겹침(occlusion) 때문에 정밀 분석에는 2D보다 불리하다. 전체 구조 파악과 프레젠테이션용으로 위치시키고, 기본 뷰는 Map으로 둔다.

### Facets — 대상/방법 패널
초록에서 **연구 대상**, **방법**, **응용 분야**를 추출해 패싯 필터로 제공. Map의 색상 인코딩과 연동되어 "이 갈래는 주로 무엇을 다루는가"를 색으로 보여준다.

추출 단계별 계획:
1. **1단계 (무료·즉시)** — OpenAlex의 `topics`/`concepts` 필드 + 저자 키워드를 그대로 사용
2. **2단계** — 초록에 c-TF-IDF를 적용해 클러스터별 특징 용어 추출
3. **3단계 (선택)** — 로컬 LLM으로 초록당 `{대상, 방법, 응용}` 구조화 추출. 1만 편이면 로컬 7B 모델로 수 시간. 품질은 좋지만 필수는 아님

## 6. 수집 전략 — 실측으로 바뀐 것

M0 탐색 중 OpenAlex 실측에서 나온 세 가지가 설계를 바꿨다.

### RAG만으로는 Flow 뷰가 성립하지 않는다

`"retrieval-augmented generation"` 연도 분포 (OpenAlex, 2026-08 기준):

| 연도 | RAG | information retrieval |
|---|---:|---:|
| 2014–2019 | 3편 | 약 3,000편/년 |
| 2022 | 23 | 2,896 |
| 2023 | 196 | 3,272 |
| 2024 | 2,980 | 4,044 |
| 2025 | 9,345 | 5,251 |
| 2026 (부분) | 14,256 | 8,311 |

RAG는 **2023년 이전이 사실상 비어 있다.** 이대로 수집하면 시간 윈도우 대부분이 비고 마지막 두 칸에 전체가 몰려 — "갈래가 무엇에서 뻗어 나왔는가"를 보일 수 없다.

**IR을 함께 모으는 것이 선택이 아니라 전제조건이다.** IR이 2010년대 척추를 대고, dense retrieval / DPR(2020–22)이 다리가 되며, RAG가 2023년에 갈라져 폭발하는 구조 — 이게 정확히 Flow 뷰가 보여줘야 할 그림이다.

### 연도별 할당량 + 피인용순 정렬로 뽑는다

cursor로 앞에서부터 1만 편을 받으면 표본이 최근에 쓸린다. 대신:

- 연도마다 할당량을 둔다 (2014–2026, 연 750편 → 목표 9,750편)
- 각 연도 안에서 `sort=cited_by_count:desc`로 상위를 가져온다

시간축이 고르게 채워지면서 각 시기의 영향력 있는 논문이 들어온다. 정렬 수집은 cursor가 아닌 page 방식을 쓰지만, 연도별 할당량이 page 상한(1만 건) 아래라 문제가 없다.

### 문헌 타입을 article로 좁히면 절반을 버린다

RAG 검색 결과의 타입 분포:

| 타입 | 편수 |
|---|---:|
| preprint | 9,205 |
| article | 6,854 |
| conference-paper | 6,733 |
| 그 외 (dissertation, dataset, ...) | 3,225 |

**preprint가 가장 큼다.** AI/CS는 arXiv 프리프린트와 학회 논문이 주 무대라 `type:article`만 받으면 분야의 절반 이상을 버리게 된다. 세 타입을 모두 받는다: `type:article|preprint|conference-paper`.

## 7. 파이프라인

각 단계는 디스크에 아티팩트를 남기고, 다음 단계는 캐시를 재사용한다. 쿼리를 바꿔도 이미 임베딩한 논문은 다시 계산하지 않는다.

```
collect   쿼리 → 원본 JSON (불변 보관)
   ↓
normalize 통일 스키마로 변환, DOI/제목 정규화로 중복 제거
   ↓
embed     초록 → 벡터  [캐시 키: hash(title+abstract+model_id)]
   ↓
project   PCA(50차원) → UMAP(2D, 3D)
   ↓
cluster   HDBSCAN → c-TF-IDF 라벨링
   ↓
temporal  시간 슬라이스 클러스터링 → 흐름 가중치 계산
   ↓
serve     FastAPI + 브라우저
```

**좌표 안정성** — 논문을 추가할 때마다 UMAP을 새로 돌리면 지도가 통째로 뒤집혀 사용자가 방향 감각을 잃는다. 대응: UMAP 모델을 저장해두고 신규 논문은 `transform()`으로만 투영한다. 전체 재학습은 명시적 `--refit` 플래그로만.

| **UMAP 거리 왜곡** | 잘못된 해석 유도 | 인용 흐름과 교차 검증. UI에 "클러스터 간 거리는 의미가 제한적" 명시 |

| **시간 슬라이스 클러스터 불안정** | Flow 뷰가 지저분 | 슬라이스별 최소 클러스터 크기를 비례 조정, 흐름 가중치 하한선 적용 |

## 10. 명시적 비목표

범위를 지키기 위해 **하지 않을 것**:

- 논문 전문(full-text) 수집 — 초록만 다룬다
- 저자/기관 단위 계량서지학 분석 (h-index, 협업 네트워크 등) — 별도 프로젝트
- 다중 사용자 / 계정 / 클라우드 배포 — 로컬 단일 사용자
- 실시간 자동 갱신 — 수집은 명시적 실행
