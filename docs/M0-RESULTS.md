## 이 과정에서 고친 것

### 페이지네이션 오프셋 버그

마지막 페이지에서 `per-page`를 남은 개수(150)로 줄였는데, OpenAlex는 오프셋을 `(page-1) × per_page`로 계산한다. 4번째 페이지가 오프셋 600이 아닌 450을 가리켜 **150편 전부가 3페이지와 중복**됐다.

연도마다 정확히 750 → 600편으로 떨어지는 규칙성이 단서였다. `per-page`를 고정하고 초과분을 클라이언트에서 잘라내는 것으로 해결. 검증: 겹침 150/150 → 0/150.

> 처음엔 정렬 동점 처리를, 그다음엔 프리프린트/게재판 중복을 의심했다. 둘 다 틀렸다. 규칙적인 손실은 데이터 특성이 아니라 코드 산술을 의심해야 했다.

### DuckDB 삽입 병목

연도당 인용 4만 행 삽입이 분 단위로 걸렸다.

| 방식 | 시간 (29,266행) |
|---|---:|
| `executemany` | 매우 느림 |
| 다중 행 `VALUES` | 47.5초 |
| 기본키 제거 + plain INSERT | 47.5초 |
| **Arrow 등록 + `INSERT ... SELECT`** | **12.0초** |

행별 실행 계획도 기본키 충돌 검사도 원인이 아니었다. 병목은 **파라미터 바인딩 자체**였고, 그걸 통째로 우회하는 Arrow 경로만이 효과가 있었다. `pyarrow`는 선택이 아니라 필수 의존성이다.
