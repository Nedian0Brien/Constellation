# 앱에서 새 논문 지도를 만든다

연구 도구 기획(`docs/RESEARCH-TOOL-PLAN.md`) 로드맵의 2단계다. 좌측 사이드바 개편(뷰 전환을 상단바로, 사이드바 맨 위에 지도 선택기)에서 지도 선택기가 부를 기능 가운데 "새 논문 지도 추가"의 백엔드다. 같은 묶음의 나머지는 별도 intent로 이어서 한다.

1. 이 intent: 새 지도 만들기와 작업 실행기
2. 외부 출처 논문 검색과 지도에 논문 추가
3. 사이드바 개편(화면)

## 문제

- 새 지도는 Python CLI로만 만든다. 수집 정의가 코드 상수(`backend/constellation/ingest/queries.py`의 `QuerySet`)라서 새 분야를 보려면 코드를 고치고, `collect`부터 `lineage`까지 명령 10개를 순서대로 실행해야 한다(README "수집과 분석").
- 앱은 분석 DB를 읽기 전용으로 열고(`crates/constellation-core/src/db.rs:36`) API와 Tauri 명령은 전부 조회다. 앱에서 파이프라인을 실행할 방법이 없고, 실행 중 진행 상황이나 실패 원인을 앱에서 볼 수 없다.
- 수집 방식이 "검색어 + 연도별 할당량" 하나뿐이다. OpenAlex 토픽으로 분야를 고르거나, 알고 있는 논문 몇 편에서 출발해 인용 관계로 넓히는 방법이 없다.

## 원하는 결과

- 새 지도를 세 가지 방식으로 정의한다. 공통 입력은 지도 이름과 임베딩 모델(기본 `scincl`)이다.
  - **검색어**: 검색어 목록(OR 결합), 연도 범위, 연도별 편수. 지금 `QuerySet`과 같은 항목이다.
  - **OpenAlex 토픽**: 토픽(또는 서브필드·필드) 하나 이상, 연도 범위, 연도별 편수.
  - **시드 논문**: DOI 목록과 확장할 편수. 시드의 참고문헌과 피인용 논문으로 넓힌다.
- 실행 전에 예상 수집 편수를 보여 준다(OpenAlex `count`).
- 정의를 제출하면 작업 하나가 수집 → backfill → enrich → embed → project → cluster → hierarchy → name → flow → lineage를 차례로 실행한다. 끝나면 지도 목록(`/api/runs`, Tauri `runs`)에 새 지도가 나타나고, 지금 지도처럼 다섯 뷰가 모두 열린다.
- 작업 상태를 조회할 수 있다: 현재 단계, 단계 안의 진행률(편수 기준), 로그, 실패한 단계와 오류 메시지. 실행 중인 작업을 취소할 수 있다.
- 앱을 다시 열어도 최근 작업의 결과(성공·실패·취소)와 로그를 볼 수 있다.
- 실패하거나 취소한 작업의 결과물은 지도 목록에 나타나지 않고, 기존 지도에도 영향이 없다.
- `codex`·`claude` CLI 로그인이 없어 이름 짓기를 못 하면 c-TF-IDF 라벨로 지도를 완성하고, 작업 결과에 그 사실을 표시한다.
- 수집 정의는 코퍼스의 `definition`(JSON)에 남는다. 같은 정의로 CLI에서도 지도를 다시 만들 수 있다.
- 기존 코드 상수 세트(`rag-ir`, `physical-ai` 등)로 하는 CLI 수집은 지금처럼 동작한다.
- 데스크톱 앱(Tauri 명령)과 브라우저 모드(`constellation-serve`)가 같은 기능을 제공한다.

## 영향 범위

- `backend/constellation/`: 수집 정의 데이터화, 토픽·시드 수집, 전 단계 실행 명령과 진행 이벤트 출력
- `crates/constellation-core`, `crates/constellation-serve`, `src-tauri`: 작업 실행기, 작업 API, 쓰기 경로
- `frontend/src/api.ts`: 작업 API 클라이언트(화면은 3번 intent)
- `README.md`, `docs/ARCHITECTURE.md`
- 데이터: `data/constellation.duckdb`, `data/embeddings/`, `data/models/`
- 결정: minjaepark

## 제약

- 기존 지도의 좌표·클러스터·영역 이름을 바꾸지 않는다.
- 파이프라인은 저장소 `.venv`의 Python을 쓰고 키는 `.env`에서 읽는다(기획 9절 결정). 런타임 번들은 배포 단계에서 한다.
- OpenAlex 무료 키 한도는 하루 $1이다. 실행 전 예상 편수를 보여 줘서 한도를 넘는 수집을 사용자가 알고 시작하게 한다.
- 한 번에 작업 하나만 실행한다.
- 워크트리에는 `data/`가 없으므로 개발과 검증은 `CONSTELLATION_DATA_DIR`로 복사본을 가리켜 한다.

## 범위 밖

- 새 지도 만들기 화면, 작업 진행 표시, 사이드바 개편(3번 intent)
- 외부 논문 검색, 지도에 논문 추가, 증분 배치(2번 intent)
- Zotero 컬렉션·BibTeX로 지도 만들기
- 수집 결과 선별(주제 밖 논문 제외 후 재계산)
- 기존 코퍼스를 다른 임베딩 모델로 다시 투영하는 지도
- 런타임 번들, 키체인, 서명·공증(배포 단계)

## 열린 질문

1. **작업 중 기존 지도 조회.** DuckDB는 쓰는 프로세스가 있으면 다른 프로세스가 같은 파일을 열지 못한다.
   - 답(2026-10-06, 사용자 결정): 작업이 DB에 쓰는 동안 앱이 분석 DB 연결을 닫는다. 그동안 지도·검색·상세 조회는 되지 않고, 앱은 작업 중이라는 상태를 돌려준다. 작업이 끝나면(성공·실패·취소 모두) 연결을 다시 연다. 복사본에서 실행하고 교체하는 방식(가)은 쓰지 않는다.
