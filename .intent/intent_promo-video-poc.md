# Remotion 홍보 영상 PoC

## 문제

Constellation을 소개할 30초 티저 영상(가로 16:9)을 만들려고 한다. 영상에서 가장 강한 장면은 실제 데이터로 그린 연구 지도(별 지도)다. 하지만 이 앱의 deck.gl 지도를 Remotion에서 프레임 단위로 정확하게 렌더할 수 있는지 아직 확인하지 않았다. 확인하지 않은 채로 30초 전체를 짜면 핵심 장면이 기술적으로 막혔을 때 작업을 통째로 버리게 된다.

## 원하는 결과

- 저장소 안에 Remotion 프로젝트가 생기고, 명령 하나로 MP4를 렌더할 수 있다.
- 1920×1080, 30fps로 약 5초짜리 핵심 장면을 렌더한 MP4가 나온다. 장면 내용은 실제 run 데이터로 그린 지도에서 시작해 상위 분야 → 하위 분야 → 논문 하나로 파고드는 카메라 줌이다.
- 렌더된 영상에서 확인할 것:
  - 모든 프레임에 점이 빠짐없이 그려진다. 빈 프레임이나 덜 그려진 프레임이 없다.
  - 카메라가 끊기지 않고 부드럽게 움직인다.
  - 분야 라벨과 논문 제목이 읽힌다.
- 점·색·라벨은 앱과 같은 규칙으로 그린다. 앱의 렌더링 코드를 재사용할 수 있는 만큼 재사용하고, 영상 전용으로 다시 짠 부분은 보고에 적는다.
- 30초 티저를 어떤 장면으로 구성할지 스토리보드 초안이 함께 나온다. 이번에 렌더하는 것은 그중 첫 핵심 장면 하나다.

## 영향 범위

- 새 Remotion 프로젝트 디렉터리와 영상용 데이터 스냅샷.
- 앱(frontend, src-tauri, crates, backend)의 동작은 바뀌지 않는다. 지도 코드를 재사용하기 쉽게 하려고 앱 코드를 고쳐야 한다면, 동작이 같은 리팩터링에 한해서만 고친다.
- 결정권자: Dennis Park.

## 제약

- Remotion 라이선스: 개인 명의로 만든다(사용자 확인). 개인은 무료 라이선스 대상이다.
- 렌더는 이 Mac의 로컬 환경에서 한다. 클라우드 렌더(Lambda)는 쓰지 않는다.
- 영상에는 가짜 데이터가 아니라 실제 run 데이터(`data/constellation.duckdb`)를 쓴다.

## 범위 밖

- 30초 티저 전체 렌더. 이번에는 핵심 장면 하나만 렌더한다.
- 내레이션, 음악, 효과음.
- 에이전트 채팅·논문 목록 같은 UI 장면, 로고 애니메이션, 엔딩 카드.
- 세로(9:16) 버전과 SNS용 다른 비율.
- 배포와 업로드.

## 열린 질문

- 30초 티저 본편에 내레이션이나 음악을 넣을지. PoC에는 영향이 없어서 본편 단계에서 정한다.
- 어느 run(모델) 데이터를 쓸지. spec 단계에서 DB의 run 목록을 보고, 가장 보기 좋은 run을 골라 제안한다.
