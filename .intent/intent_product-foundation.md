# 컨스텔레이션 제품 기반 구축

## 문제

논문 지도와 분석 화면은 구현되어 있지만, 연구자가 탐색을 이어갈 공통 앱 구조와 상태 복원이 부족하다. 기능을 확장할 때 사용할 일관된 컴포넌트와 데이터 요청 처리 기반이 필요하다.

## 원하는 결과

- 왼쪽 탐색, 중앙 분석 화면, 오른쪽 상세 패널을 갖춘 앱 셸에서 기존 다섯 화면을 사용할 수 있다.
- 패널 크기를 조절하고 다시 열었을 때 배치를 복원할 수 있다.
- 검색·필터·선택한 논문 등 탐색 상태를 새로고침과 뒤로 가기 후에도 복원할 수 있다.
- 논문 목록에서 정렬·필터·선택을 하고 지도 및 논문 상세로 이어갈 수 있다.
- 데이터 로딩·빈 결과·오류·재시도가 공통된 방식으로 표시되고 실제로 동작한다.

## 영향 범위

연구 분야를 탐색하는 사용자, 프론트엔드 공통 셸·컴포넌트·탐색 상태·데이터 요청과 필요한 논문 조회 API. 제품 범위와 단계별 수락은 사용자가 결정한다.

## 제약

React·Vite, shadcn/ui와 Resizable, TanStack Router·Query·Table, 기존 deck.gl·FastAPI 구성을 사용한다. 기존 분석 기능과 데이터·모델 산출물을 보존한다. 실제 API와 브라우저에서 탐색 및 복원 동작을 검증한다.

## 범위 밖

프로젝트 생성·관리와 수집·분석 작업 실행의 전체 제품 흐름, 사용자 계정·협업·클라우드 배포, Tauri 패키징, 자유 도킹, Scopus 연결, 분석 알고리즘 교체와 코퍼스 재수집은 후속 변경으로 다룬다.

## 열린 질문

2026-09-09 사용자의 “일단 Spec까지는 작성해놔” 지시로 범위와 식별자를 수락한 것으로 반영했다. Spec 작성 후 디자인 시스템 수립을 선행하고 제품 기반 Plan과 구현을 진행한다. 기존 실데이터와 모델 산출물의 위치는 Spec 단계에서 조사하고 실제 화면 검증에 사용할 환경을 정한다.
