# 외부 출처에서 논문을 찾아 지도에 추가한다

연구 도구 기획(`docs/RESEARCH-TOOL-PLAN.md`) 로드맵의 3단계다. 좌측 사이드바 지도 선택기의 "논문 검색"과 "새 논문 추가"가 부를 백엔드다. 같은 묶음의 1번(새 지도 만들기, #26)은 머지됐고, 3번(사이드바 화면)은 이 작업 뒤에 한다.

## 문제

- 앱의 검색은 지도에 이미 있는 논문만 찾는다(지도 안 검색 pill, `/api/matches`). 코퍼스 밖 논문을 찾을 방법이 없다.
- 알고 있는 논문(DOI, arXiv ID, OpenAlex ID)을 지도에 넣을 방법이 없다. 지금 논문을 늘리려면 수집 정의를 고쳐 지도를 처음부터 다시 만들어야 한다.
- 다시 만들면 좌표·클러스터 번호·영역 이름이 모두 바뀐다. 클러스터링용 PCA·UMAP 10차원 모델을 저장하지 않고(`analyze/cluster.py:151-160`), sklearn `HDBSCAN`에는 예측 메서드가 없기 때문이다. 이름 짓기도 비결정적이다.

## 원하는 결과

- **외부 논문 검색.**
  - 검색어로 OpenAlex를 검색해 제목, 연도, 저자, 발표처, 피인용 수, DOI, 초록 유무를 돌려준다. 페이지당 25편이다.
  - 결과마다 현재 지도에 이미 있는 논문인지 표시한다.
  - DOI·arXiv ID·OpenAlex ID/URL을 넣으면 검색 대신 그 논문을 바로 찾는다.
- **지도에 추가.** 검색 결과나 식별자 목록(여러 편)을 현재 지도에 추가한다.
  - 각 논문은 지도의 저장된 투영 모델로 2D·3D 좌표를 얻어 지도·목록·상세·지도 안 검색에 나타난다.
  - 각 논문은 기존 클러스터 하나에 배정되거나 미분류가 된다. 결과에 어느 주제로 들어갔는지 알려 준다.
  - 참고문헌·피인용 관계로 지도 안 논문과 연결된다.
  - 초록은 OpenAlex, 없으면 Semantic Scholar에서 찾는다. 둘 다 없으면 제목만으로 임베딩하고 그 사실을 표시한다.
- 추가한 논문은 "추가한 논문"으로 구분된다. 언제 추가했는지 알 수 있고, 추가한 논문만 골라 볼 수 있다.
- 추가한 논문을 지도에서 다시 뺄 수 있다. 수집으로 들어온 논문은 뺄 수 없다.
- 추가는 새 지도 만들기와 같은 작업 실행기에서 돈다. 진행 상황·로그·취소·실패 정리·작업 중 조회 503이 그대로 적용된다.
- 추가한 논문이 지도 논문 수의 10%를 넘으면 결과에 전체 재계산을 권하는 표시를 붙인다. 이 기준은 기획 5.3절의 제안값이다.
- 데스크톱 앱과 브라우저 모드가 같은 기능을 제공한다.

## 영향 범위

- `backend/constellation/`: OpenAlex 검색·단건 조회, 증분 배치 명령, 추가 논문 소속 기록
- `crates/constellation-core`: 추가한 논문 표시와 목록 필터
- `crates/constellation-jobs`, `crates/constellation-serve`, `src-tauri`: 검색 API, 추가·빼기 작업
- `frontend/src/api.ts`: 클라이언트 함수(화면은 3번 intent)
- `README.md`, `docs/ARCHITECTURE.md`
- 결정: minjaepark

## 제약

- 기존 논문의 좌표, 클러스터 번호, 영역 이름을 바꾸지 않는다.
- OpenAlex 검색은 1,000회에 $1이고 무료 예산은 하루 $1이다. DOI·ID 단건 조회는 무료다(2026-10-06 확인). 화면은 입력을 debounce해서 부른다.
- 키는 `.env`에서 읽는다. Python은 저장소 `.venv`를 쓴다.
- 워크트리에는 `data/`가 없으므로 실데이터 검증은 복사본에서 한다.

## 범위 밖

- 검색·추가 화면, 추가한 논문 강조 레이어, 사이드바 개편(3번 intent)
- BibTeX·RIS·Zotero·PDF 가져오기
- 전체 재계산 실행 화면. 지금은 CLI로 `build`를 다시 실행한다.
- 새 논문 모니터링, 컬렉션, 태그
- 계층 트리·갈래 흐름·인용 계보 갱신. 추가한 논문은 전체 재계산 때 반영된다.

## 열린 질문

답(2026-10-06, 사용자 결정):

1. **클러스터 배정 방법.** 기존 지도에는 클러스터링 모델이 저장돼 있지 않다. 그래서 (가)로 한다. 임베딩 공간에서 가장 가까운 지도 안 논문 k편의 클러스터 다수결로 배정하고, 이웃이 대부분 미분류면 미분류로 둔다. cluster 단계를 고쳐 HDBSCAN 모델을 저장하는 방식(나)은 기존 클러스터와 이름이 바뀌므로 쓰지 않는다.
2. **추가 범위.** (가)로 한다. 논문을 코퍼스에 소속시키고 지금 보고 있는 지도에만 배치한다. 같은 코퍼스의 다른 지도는 다음 재계산 때 포함된다.
